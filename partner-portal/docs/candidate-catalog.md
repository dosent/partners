# Внутренний каталог кандидатов

Раздел «Кандидаты» доступен сотрудникам с разрешением `candidate.manage` (роль Resource Manager). Каталог использует серверное хранение; демонстрационный пул к нему не подключён.

Перед использованием администратор публикует тексты `candidates.*` для нужной локали через существующий редактор текстов. Список ключей находится в `src/admin/candidateContent.js`; в редакторе они доступны среди дополнительных ключей. Новые тексты не делают прежние публикации регистрации недействительными. Отсутствующие переводы вводятся людьми; до публикации полного набора каталог сообщает об отсутствии подготовленного содержимого.

## Добавление и работа с профилем

1. Откройте каталог и выберите добавление кандидата.
2. Укажите роль, навыки, опыт в годах и месяцах, описание, часовую ставку кандидата и валюту. Грейд необязателен; нулевой опыт допустим.
3. Явно отметьте доступность и приложите CV: PDF или DOCX до 20 МБ.
4. Сохраните профиль. Код присваивается сервером, данные доступны после перезагрузки страницы.

По умолчанию показаны доступные кандидаты. Фильтр позволяет увидеть недоступных или всех. Поиск учитывает код, внешний ключ, роль, навыки и описание, но не содержимое CV. Список разбит на страницы по 20 записей.

Доступность — ручная отметка сотрудника. Она не подтверждает занятость в Jira, не резервирует специалиста и не назначает его на заявку. Назначение ответственного Resource Manager на заявку остаётся отдельной операцией.

## Внешний ключ Jira

Поле `externalKey` отображается как «Внешний ключ (Jira)». Его можно оставить пустым, затем заполнить, изменить или очистить. Непустые значения уникальны с учётом регистра; максимальная длина — 200 символов, управляющие символы запрещены. Система обрезает пробелы по краям и хранит пустое значение как отсутствие связи.

Ключ не заменяет внутренний ID/код кандидата. Сохранение значения не обращается к Jira и не проверяет существование внешней записи. Конкретная сущность Jira и правила будущей синхронизации согласуются на следующем этапе.

## Ставки, CV и конфликты

Ставка кандидата хранится с валютой и единицей «за час», временем и автором изменения. Изменение только профиля, доступности или внешнего ключа не меняет время и автора ставки. Она отделена от клиентской ставки. Расчёты маржи и эффективности, налоги и конвертация валют появятся только после согласования формул.

CV проверяется до сохранения. При замене создаётся новая версия; предыдущие версии остаются внутренними, а скачивание выдаёт текущую проверенную версию. При ошибке проверки, хранилища или записи предыдущий файл сохраняется. CV не публикуется партнёрам, автоматическое обезличивание не выполняется.

Если карточка уже изменена другим сотрудником, сохранение возвращает конфликт. Введённые значения остаются в форме для сверки; обновите карточку и перенесите нужные правки в актуальную версию. Занятый внешний ключ показывается как ошибка соответствующего поля.

Если результат создания неизвестен из-за потери соединения, используйте повтор исходной отправки. Не создавайте вручную вторую карточку вместо повторной операции. После перезагрузки браузер может попросить снова выбрать исходный CV. Если сервер подтверждает, что создание отклонено и операция полностью отменена (`CANDIDATE_CREATE_REJECTED`), форма разблокируется с сохранением введённых полей; можно заменить CV и отправить исправленную карточку. Неопределённый ответ или конфликт исходного содержимого сохраняют прежний ключ повтора.

## Контракт API

Все маршруты требуют staff-сессию и `candidate.manage`; изменяющие запросы сохраняют CSRF-защиту. Сумма передаётся и возвращается строкой десятичного числа, например `"2500.50"`; валютой служит код ISO 4217.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/v1/admin/candidates` | Поиск, фильтр `availability=AVAILABLE/UNAVAILABLE/ALL`, параметры `q/page/size` |
| `GET /api/v1/admin/candidates/{id}` | Карточка с текущей ставкой, метаданными CV и общей версией |
| `POST /api/v1/admin/candidates` | Multipart: JSON-часть `profile`, файл `cv`, заголовок `Idempotency-Key` |
| `PUT /api/v1/admin/candidates/{id}` | JSON-профиль со ставкой и `expectedVersion` |
| `PUT /api/v1/admin/candidates/{id}/cv` | Multipart: `cv` и `expectedVersion` |
| `GET /api/v1/admin/candidates/{id}/cv` | Скачивание текущего CV после проверки доступа |

JSON-профиль содержит `role`, `grade`, `skills`, `experienceMonths`, `description`, `availability`, `externalKey`, `hourlyRate: { amount, currency }`. Для изменения дополнительно требуется `expectedVersion`.

Изменения ставки и CV также повышают общую версию карточки. Повтор создания с тем же пользователем, ключом и исходным содержимым возвращает существующего кандидата; изменение содержимого при том же ключе отклоняется. Профиль, ставка и метаданные CV сохраняются в одной транзакции, загрузка нового объекта компенсируется при откате.

Ошибки используют штатный формат `code/message/traceId/fieldErrors`: 400 — данные, 401/403 — доступ, 404 — отсутствие, 409 — версия/ключ/повторная операция, 413 — размер файла, 422 — антивирусное отклонение, 503 — недоступная проверка/хранилище. Подробный контракт доступен в OpenAPI.
