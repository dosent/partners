# Архитектурный дизайн партнёрского портала

## Решение

Целевая система строится как модульный монолит: React/Vite SPA и единый backend на Java 21 / Spring Boot 3 с PostgreSQL 15+. Доменные модули разделяют регистрацию, партнёров, лиды, заявки, кандидатов, финансы, документы, уведомления, локализацию, аудит и интеграции. Модуль публикует application interface и не предоставляет другим модулям прямой доступ к своим repository.

JPA/Hibernate является основным механизмом CRUD и управления агрегатами. `NamedParameterJdbcTemplate + QueryHelper` используется для сложных чтений, дашбордов, отчётов и массовых операций. Хранимые процедуры и `SimpleJdbcCall` запрещены; схема изменяется только Liquibase, бизнес-логика выполняется приложением.

Партнёры входят через Yandex ID, сотрудники — через LDAP. Локальные пароли и собственная 2FA не создаются. Сервер выдаёт защищённую web-сессию и проверяет роль, владельца и область данных на каждой операции.

## Границы модулей

| Модуль | Ответственность |
|---|---|
| `access` | Yandex ID, LDAP, web-сессии и роли |
| `partner` | заявки на регистрацию, партнёры, профиль и реквизиты |
| `lead` | лиды, атрибуция, комментарии и статусы |
| `staffing` | заявки на специалистов и SLA |
| `candidate` | анонимизированные профили, предложения и решения |
| `finance` | ставки, оборот, начисления, выплаты и споры |
| `document` | метаданные, версии, права и объектное хранилище |
| `notification` | центр уведомлений и повторная доставка |
| `localization` | RU/KZ/EN, оферты, согласия и брендинг |
| `audit` | неизменяемая история критических действий |
| `integration` | CRM, реестры, КЭДО, курсы валют и внешние adapters |

## Потоки данных и ошибки

Контроллеры принимают DTO, вызывают application service и возвращают DTO. Application service проверяет полномочия, оркестрирует агрегаты и владеет транзакцией. JPA repository изменяет агрегаты; JDBC query service строит сложные проекции. После commit transactional outbox инициирует уведомления и интеграционные события.

Ошибки API имеют стабильный код, локализованное безопасное сообщение, `traceId` и ошибки полей. Конкурентное изменение возвращает HTTP 409. Недоступность реестра создаёт ручную проверку, а сбой дополнительного уведомления не отменяет основную операцию.

## Проверка качества

Unit tests покрывают доменную и application-логику. JPA/JDBC проверяются интеграционно на PostgreSQL Testcontainers. MockMvc проверяет контракты и серверную авторизацию, WireMock — внешние adapters, Playwright — критические пользовательские сценарии. ArchUnit контролирует границы модулей. Перед выпуском выполняются нагрузочные и security проверки.

Подробные решения и поведенческие требования находятся в OpenSpec change `full-partner-portal-specification`.
