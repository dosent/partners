# Проверки изменения manual-candidate-catalog

## Исходное состояние — 30 октября 2026 года

Работа выполнена в изолированной рабочей копии candidate-catalog, ветке codex/candidate-catalog от локальной main. Согласованные изменения спецификации с внешним ключом сохранены. CodeGraph-индекса не было; Comet probe вернул none. Исходный backend прошёл 170 тестов без ошибок и пропусков.

## Реализация и независимая проверка

Профили принадлежат candidate, ставки — finance, CV — document. Сохранение использует общую транзакцию и rollback-компенсацию S3. Внешний ключ nullable и уникален среди заполненных значений; обращения к Jira и расчёт экономики не добавлялись.

После просьбы пользователя работа разделена между агентами frontend, document/CV и e2e; родительский агент реализовал persistence, application service, API и интеграцию. Отдельный агент выполнил независимый обзор всей реализации. Он нашёл два Important замечания, оба воспроизведены и исправлены с RED→GREEN:

- Изменение только профиля больше не меняет автора/время/версию ставки. Проверены численно равные суммы и отдельное действительное изменение ставки; e2e подтверждает неизменность всей ставки после редактирования описания.
- После потери ответа подтверждённый отказ CV возвращает CANDIDATE_CREATE_REJECTED: транзакция отменена, форма разблокируется с сохранением полей. Неопределённый ответ и конфликт содержимого удерживают исходный ключ; Chromium/WebKit проверяют оба пути.

Дополнительные найденные интеграционные причины устранены:

- Для поиска навыков JSONB явно приводится к тексту. PostgreSQL-тесты проверяют буквальные проценты/подчёркивания и доступность.
- Время создаваемых/изменяемых данных нормализуется до микросекунд PostgreSQL: ответы создания и последующего чтения совпадают.
- Лимит словаря локализации расширен с 200 до 500 строк; 227 и 500 допускаются, 501 и значение длиннее 12000 символов отклоняются. Обязательные юридические и регистрационные строки не менялись.
- Старый тест 50-строчной публикации явно исключает новый необязательный namespace candidates.*, сохраняя свою проверку совместимости.
- Для изолированного порта MCP задан отдельный E2E_MCP_URL. Первые прогоны с перечисленными ошибками не использовались как основание для интеграции.

## Решения и ограничения

- Для идемпотентного резервирования используется QueryHelper и INSERT ON CONFLICT, без лишней JPA-сущности; fingerprint исходной операции хранится отдельно от редактируемого профиля.
- Существующее общее ArchUnit-правило уже охватывает candidate/finance/document; оно проверило новые реальные зависимости без дублирующего правила.
- Старый LeadDocumentService сохраняет совместимость 400 для превышения лимита через адаптацию; новый validator/API кандидатов используют 413.
- Компенсация удаления объекта S3 выполняется best effort при недоступности самого удаления; такие объекты не становятся текущим CV. Production S3/антивирус на реальном стенде в этом изменении не проверялись.
- Перед использованием нужно вручную опубликовать candidates.* для нужной локали. Переводы и production-записи не генерировались.
- Развёртывание на рабочем стенде и push не входят в выполненную локальную реализацию.
