## Why

Новые и повторно поданные заявки уже сохраняются в `MANUAL_REVIEW`, однако сотрудник не может получить их через API или принять решение. Из-за отсутствия очереди ручная проверка пока не завершает регистрационный процесс.

## What Changes

- Добавить защищённые API очереди и карточки заявки для back-office.
- Добавить API владельца для чтения статуса собственной заявки и причины решения.
- Добавить действия `approve`, `reject` и `request-changes`; последние два требуют безопасную причину, видимую владельцу заявки.
- Ограничить операции ролями `PARTNER_MANAGER` и `SYSTEM_ADMIN`.
- Аутентифицировать сотрудников через указанный LDAPS-каталог, а роли назначать и проверять внутри портала по RBAC-матрице.
- Создать начальное неизымаемое назначение `SYSTEM_ADMIN` для LDAP-логина `ivan.neshin` и API, через который системный администратор управляет ролями сотрудников.
- Сохранять актёра, время и причину в существующей неизменяемой истории статусов; конфликты параллельных решений возвращать как `409`.
- Поддержать назначение ответственного менеджера при одобрении с проверкой целевой роли.
- Добавить страницу ожидания доступа для LDAP-аутентифицированных сотрудников без ролей и back-office интерфейс, где `SYSTEM_ADMIN` выдаёт и отзывает роли.

## Capabilities

### Modified Capabilities

- `partner-application-review`: уточнить API-поведение очереди, карточки и решений.

### Added Capabilities

- `staff-access`: добавить хранимые в приложении назначения ролей и управление ими системным администратором.

## Impact

- Backend: новые API DTO, application service/policy, безопасная выборка очереди, API статуса своей заявки, расширение persistence и Liquibase.
- Access: LDAPS с FreeIPA-настройками и CA-файлом, role/permission matrix в приложении, назначения ролей в PostgreSQL, bootstrap system administrator и аудит изменений ролей.
- Frontend: staff-входной маршрут, страница ожидания назначения роли и минимальный экран управления ролями для `SYSTEM_ADMIN`; очередь модерации остаётся следующим UI-этапом.
- Интеграции государственных реестров не добавляются; каждая новая и повторно поданная заявка остаётся в `MANUAL_REVIEW`.
