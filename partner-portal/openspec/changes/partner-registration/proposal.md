## Why

Текущий портал является frontend-прототипом: регистрация не создаёт учётную запись, заявки не сохраняются, а решение сотрудника SimbirSoft и доступ к кабинету не связаны. Нужен сквозной поток регистрации физических лиц, юридических лиц и ИП с внешней идентификацией, проверкой реквизитов и ручным одобрением.

## What Changes

- Добавить RU/KZ/EN регистрацию партнёров типов «Физическое лицо», «Юридическое лицо» и «ИП»; вход партнёров первой версии — через Yandex ID, без хранения паролей партнёров.
- Сохранять заявку, согласия и принятую версию оферты; до ручного одобрения показывать партнёру только статус и причину отказа.
- Добавить back-office очередь заявок на этом же сайте для сотрудников SimbirSoft, авторизованных через LDAP; разрешить менеджеру одобрять или отклонять заявку с причиной.
- Направлять каждую новую и повторно поданную заявку на ручную проверку сотрудником SimbirSoft; автоматическую проверку через госреестры отложить.
- Добавить администрирование переводов и оферты для регистрации по RU/KZ/EN с черновиком, предварительным просмотром, публикацией и историей версий. Переводы создаются вручную.
- Использовать логотип SimbirSoft для RU/EN и логотип 17Soft для KZ; выбор соответствия логотипа локали настраивается администратором.
- Не загружать демонстрационные записи в production: разделы лидов, заявок на специалистов/кандидатов, вознаграждений, документов и профиля остаются пустыми до отдельных изменений; новые данные создаются через интерфейсы.
- Не реализовывать подтверждение email и 2FA в этом изменении.

## Capabilities

### New Capabilities

- `partner-registration`: регистрация с Yandex ID, типами партнёра, проверкой реквизитов, статусом и фиксацией согласий.
- `partner-application-review`: очередь и решения сотрудников SimbirSoft по заявкам партнёров.
- `registration-localization`: локализованные тексты регистрации, версии оферты и соответствия логотипов локалям, управляемые через back-office.
- `staff-access`: LDAP-аутентификация сотрудников и разграничение доступа к функциям модерации и локализации.

### Modified Capabilities

Нет. В `openspec/specs/` ещё нет опубликованных спецификаций.

## Impact

- Текущий React/Vite-интерфейс расширяется публичным потоком входа/регистрации партнёров и back-office разделами модерации и локализации.
- Добавляются backend API на Java 21 / Spring Boot 3, PostgreSQL 15+ и REST-контракты `/api/v1/...` согласно целевому стеку ТЗ.
- Сервисы запускаются в Docker; локальная разработка и тесты используют Docker Compose. Секреты задаются переменными окружения и не хранятся в репозитории или образах.
- Подключаются Yandex ID для внешних партнёров и LDAP для сотрудников SimbirSoft.
- Потребуются настройки OAuth-приложения Yandex ID и LDAP-групп, юридически утверждённые версии оферты на RU/KZ/EN и утверждённый графический ассет 17Soft. Подключение реестров потребует отдельного решения.
- Регистрация не включается в production до получения и публикации утверждённых текстов оферты и бренд-ассетов для всех доступных локалей.
- За пределами изменения остаются подтверждение email, 2FA, автоматический перевод, прочие разделы i18n Manager, CRM, КЭДО, а также подбор/назначение кандидатов.
- Интеграция API перечисленных в ТЗ модулей кабинета с этим изменением не выполняется; их production-данные не подменяются демонстрационными примерами.
