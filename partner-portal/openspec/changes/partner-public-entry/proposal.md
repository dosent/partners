## Why

Сейчас корневой маршрут production сразу ведёт посетителя к регистрации, поэтому у неавторизованных партнёров нет публичной страницы с описанием программы. Форма регистрации получает одну общую оферту, хотя условия должны выбираться по типу заявителя. Внутренняя админка позволяет менять роли по введённому логину, но не показывает список уже заведённых в RBAC пользователей.

## What Changes

- Добавить русскоязычный публичный лендинг для неавторизованных партнёров с переходами к регистрации и входу.
- Убрать переключатель RU/KZ/EN из пользовательского потока и использовать русскую форму.
- Разделить текст оферты на три управляемые редакции: физическое лицо, ИП и юридическое лицо; оставить общее согласие на обработку персональных данных.
- Дать администратору редактировать, версионировать и публиковать текст каждой оферты; форма показывает документ для выбранного типа и фиксирует точную принятую редакцию.
- Расширить RBAC-админку списком логинов, которым назначены роли, поиском, добавлением логина и редактированием набора ролей.
- Сохранять серверную авторизацию и аудит назначений. LDAP подтверждает личность при входе, LDAP-группы не являются источником ролей.

## Capabilities

### New Capabilities

- `partner-public-entry`: публичный лендинг, переход к регистрации, показ соответствующей оферты и фиксация согласий.
- `staff-role-administration`: просмотр и изменение RBAC-назначений сотрудников системным администратором.

### Modified Capabilities

- Нет. Детальные требования добавляются как новые capabilities; существующие решения по Yandex ID, ручной модерации, LDAP и RBAC остаются в силе.

## Impact

- Frontend: `src/App.jsx`, публичные страницы и API-клиенты партнёра; страницы и API управления регистрационным контентом и ролями.
- Backend: модули `localization`, `partner` и `access`; REST API `/api/v1`; Liquibase-миграции для отдельных редакций оферт при необходимости.
- Хранение: только текстовые оферты в PostgreSQL; загрузка PDF/файлов в этом изменении не требуется.
- Проверки: OpenSpec, проверки API/авторизации и пользовательские сценарии лендинга, регистрации, согласий и администрирования ролей.
