# Design

## Context

Портал уже содержит партнёрские REST API и web-сессию Yandex ID. Бизнес-правила и проверки владельца должны оставаться в backend. MCP — отдельный сервис-адаптер над REST API, без прямого доступа к PostgreSQL.

## Decisions

- Backend хранит только SHA-256 хеш полного случайного секрета `ppk_<uuid>_<base64url-secret>`. Партнёр управляет несколькими ключами через web-сессию; секрет показывается один раз. Отзыв немедленно действует на последующие запросы.
- MCP-клиент отправляет секрет в `X-Partner-API-Key` поверх TLS. Это собственный статический API-key механизм, не OAuth access token MCP. Ключ никогда не передаётся в URL и не логируется.
- Backend валидирует ключ при каждом REST вызове и создаёт обычный partner principal; backend остаётся доверенной границей для owner scope.
- `@McpTool` экспортируется как `x-mcp` OpenAPI extension. Каталог работает по default-deny и публикует только корректно размеченные операции.
- Generic adapter допускает только описанные OpenAPI method/path/schema. Multipart, binary и иные сложные контракты требуют явного adapter.
- MCP использует Streamable HTTP, отдельный Docker image, runtime URL backend/OpenAPI из env и не получает DB credentials.
- Каталог загружается при старте. После изменения `x-mcp` MCP контейнер перезапускается/пересоздаётся.
- Запросы и backend ответы ограничиваются по размеру и времени; ingress обязан ограничивать частоту запросов до публикации production hostname.

## Security boundaries

Управление ключами требует `PARTNER_WEB_SESSION`; MCP запрос требует действующий API key и не может использовать API key для управления другими ключами. Отсутствующий, неверный или отозванный ключ даёт 401; чужие объекты остаются недоступны через штатную backend авторизацию. В логах допустимы имя инструмента, trace ID и статус, но не ключ, payload или PII.

## Alternatives

Встроенный MCP backend противоречит требованию отдельного сервиса. Прямой доступ MCP к базе или privileged backend credential обошёл бы существующие правила доступа. Выбран REST adapter с ключом партнёра, валидируемым backend.
