# Spec Delta

## Purpose

Предоставить партнёрам безопасный способ подключать MCP-клиенты к опубликованным операциям своего кабинета.

## ADDED Requirements

### Requirement: Партнёр управляет своими MCP API-ключами

Система SHALL позволять аутентифицированному партнёру создавать, перечислять и отзывать собственные API-ключи. Полный секрет SHALL отображаться только в успешном ответе создания и SHALL NOT храниться в исходном виде. Маршруты управления SHALL требовать web-session principal и SHALL NOT принимать API-key principal.

#### Scenario: Создание и повторный просмотр ключа
- **WHEN** партнёр создаёт ключ с названием интеграции
- **THEN** backend SHALL выдать криптографически случайный секрет и показать его один раз
- **AND** список SHALL содержать безопасное резюме ключа без секрета

#### Scenario: Отзыв ключа
- **WHEN** владелец отзывает свой ключ
- **THEN** последующие MCP и backend запросы с этим ключом SHALL завершаться отказом аутентификации

#### Scenario: Попытка управления ключом другого партнёра
- **WHEN** партнёр перечисляет или отзывает ключ с чужим owner scope
- **THEN** система SHALL NOT раскрывать данные или изменять чужой ключ

### Requirement: API key аутентифицирует партнёра

Партнёрские MCP и REST запросы SHALL передавать ключ в `X-Partner-API-Key` по TLS. Backend SHALL проверять хеш и статус ключа при каждом запросе и SHALL применять текущие проверки роли и владельца. Ключ SHALL NOT приниматься из URL или записываться в логи.

#### Scenario: Ключ отсутствует, неверен или отозван
- **WHEN** запрос не содержит действительный API key
- **THEN** backend SHALL отвечать 401 даже при наличии одновременно валидной web-сессии

#### Scenario: Чужой объект
- **WHEN** партнёр с действительным ключом запрашивает объект другого партнёра
- **THEN** backend SHALL отклонить доступ согласно обычной политике owner scope

### Requirement: MCP публикует только явно разрешённые OpenAPI операции

Каталог MCP SHALL включать только операции с корректным `x-mcp.enabled=true`, созданным из backend `@McpTool`. Неразмеченные, дублирующие имя или некорректные операции SHALL NOT публиковаться. Клиент SHALL NOT задавать произвольный URL или HTTP method.

#### Scenario: Неразмеченный API
- **WHEN** endpoint присутствует в OpenAPI без `x-mcp.enabled=true`
- **THEN** операция SHALL отсутствовать в MCP `tools/list`

#### Scenario: Generic JSON tool call
- **WHEN** клиент вызывает опубликованный JSON инструмент с аргументами по schema
- **THEN** MCP SHALL вызвать фиксированные method/path backend операции и передать тот же ключ в `X-Partner-API-Key`
- **AND** backend SHALL повторно проверить ключ и права владельца

#### Scenario: Multipart или binary операция
- **WHEN** каталог содержит поддерживаемую multipart/binary операцию
- **THEN** MCP SHALL обрабатывать её явным именованным adapter с лимитом загрузки 20 MB и ограниченным размером ответа
- **AND** секрет, payload и PII SHALL NOT попадать в логи

### Requirement: MCP работает отдельным сервисом

MCP SHALL развёртываться отдельным Docker image и SHALL NOT иметь доступ к PostgreSQL credentials. Сервис SHALL использовать Streamable HTTP, проверять ключ через backend до обработки каждого MCP HTTP запроса и ограничивать время и размер запросов/ответов.

#### Scenario: Перезапуск каталога
- **WHEN** backend OpenAPI `x-mcp` изменился
- **THEN** MCP SHALL загрузить новый каталог после перезапуска или пересоздания контейнера

#### Scenario: Ошибка backend
- **WHEN** backend возвращает ошибку, timeout или trace ID
- **THEN** MCP SHALL сохранить безопасный машинный код/смысл ошибки и trace ID без раскрытия stack trace или секрета
