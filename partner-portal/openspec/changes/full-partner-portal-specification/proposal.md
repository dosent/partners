## Why

Существующий партнёрский портал реализован как интерактивный frontend-прототип с данными в памяти браузера. Для разработки production-системы нужен единый согласованный контракт, охватывающий все показанные интерфейсы, внутренние роли, серверные API, хранение данных, интеграции и эксплуатационные требования.

## What Changes

- Зафиксировать целевую архитектуру модульного монолита: React/Vite SPA, Java 21 / Spring Boot 3 backend, PostgreSQL 15+, объектное файловое хранилище и REST API `/api/v1`.
- Описать публичный лендинг, вход через Yandex ID, регистрацию физических лиц, ИП и юридических лиц, проверку реквизитов и модерацию заявок.
- Перевести все разделы партнёрского кабинета из демонстрационных данных на серверные доменные модули: обзор, лиды, заявки на специалистов, кандидаты, вознаграждения, документы, профиль и уведомления.
- Описать back-office для менеджера партнёров, Resource Manager, финансового контролёра и системного администратора.
- Установить JPA/Hibernate основным механизмом CRUD и связей; применять `NamedParameterJdbcTemplate` и `QueryHelper` для сложных выборок, отчётов и массовых операций.
- **BREAKING**: полностью запретить хранимые процедуры и `SimpleJdbcCall`; бизнес-операции выполняются в приложении и обычных SQL-запросах, схема изменяется только Liquibase.
- Зафиксировать ручное управление RU/KZ/EN локализациями, юридическими текстами и брендингом без автоматического перевода.
- Зафиксировать безопасность, аудит, хранение файлов, резервное копирование, мониторинг, тестирование, контейнеризацию и критерии приёмки.
- Не добавлять локальные пароли партнёров, смену пароля и 2FA: партнёры входят через Yandex ID, сотрудники — через LDAP.

## Capabilities

### New Capabilities

- `public-registration-access`: публичный лендинг, локали, Yandex ID, регистрация партнёра и статус заявки.
- `partner-dashboard-profile`: сводный экран, профиль, реквизиты и настройки партнёра.
- `lead-management`: создание, атрибуция, обработка и сопровождение лидов.
- `staffing-request-management`: заявки на специалистов, требования, SLA и работа Production.
- `candidate-management`: анонимизированный пул, предложения, запрос назначения и решения партнёра.
- `reward-finance-management`: начисления, ставки, согласование, выплаты и финансовые обращения.
- `partner-document-management`: документы, версии, загрузка, скачивание и согласование.
- `portal-notifications`: пользовательские и внутренние уведомления о доменных событиях.
- `back-office-administration`: внутренние очереди, RBAC, модерация, справочники и аудит.
- `localization-content-management`: ручное управление RU/KZ/EN, офертами, согласиями и логотипами.
- `platform-quality-security`: API-конвенции, защита данных, наблюдаемость, производительность и эксплуатация.

### Modified Capabilities

Нет: опубликованный каталог `openspec/specs/` отсутствует. Активное изменение `partner-registration` остаётся источником уточнённых решений по onboarding до последующей синхронизации или архивации.

## Impact

- Frontend: существующее React/Vite приложение, все экраны и формы прототипа, новые публичные и back-office маршруты.
- Backend: новый модульный монолит Java 21 / Spring Boot 3 с доменными модулями и REST API.
- Данные: PostgreSQL 15+, Liquibase, JPA/Hibernate, JDBC/QueryHelper для специализированных запросов; без хранимых процедур.
- Интеграции: Yandex ID, LDAP, государственные реестры, CRM, КЭДО, валютные курсы, файловое хранилище и опциональный LLM для анализа ТЗ после отдельного согласования.
- Эксплуатация: Docker, Docker Compose, Kubernetes, секреты только из окружения/secret store, мониторинг, аудит и резервное копирование.
- Документация: полное техническое задание, OpenAPI 3 и обновлённые правила `AGENTS.md`.
