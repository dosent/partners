# Рабочий стенд пользователя на 8088

Рабочий адрес: `http://vm-neshin-test.simbirsoft:8088/`. Проект Docker Compose: `par-1-diagnostic`. Не путать с отдельным проектом `partner-portal-staging`, который в текущем окружении опубликован на 18088.

Скрипт `deploy/staging/deploy.sh` не обновляет рабочий экземпляр 8088: у него другой project name, runtime env и каталог релизов. Перед развёртыванием на 8088 определяйте текущую конфигурацию по Compose labels контейнера, публикующего этот порт.

## Конфигурация и данные

Runtime-каталог находится на VM в `~/.config/partner-portal/runtime-8088`. Его конфигурационные JSON содержат runtime-переменные, поэтому остаются только на VM с правами 0600. Не выводите содержимое, не переносите в Git, архив исходников или контекст Docker build.

В конфигурации приложения описаны frontend/backend/mcp; PostgreSQL, MinIO и ClamAV уже работают в проекте и общей внешней сети. Обновление приложения выполняется с тем же project name и той же сетью. Не создавайте новые хранилища и не запускайте `down -v` либо `--remove-orphans` для этого обновления.

Новая конфигурация создаётся на VM из текущей с заменой только версий образов. Environment, порты, mounts, сертификат LDAP и остальные параметры сохраняются. Конфигурацию безопаснее хранить вне каталога исходников: `runtime-8088/configs/<sha>.json`; рабочий каталог релиза передаётся Compose через `--project-directory`.

Перед заменой сохраняйте прежние конфигурацию и image tags для отката. Runtime использует production-образы без тестовых auth adapters; профили e2e/auth-test недопустимы. Наличие LDAP и остальные настройки входа определяются существующей конфигурацией, а не примером env из репозитория.

## Сохранение исправлений

Перед обновлением сравните Git-версию текущего frontend с целевым релизом. На 30 октября 2026 года исходный релиз f032145 содержал отдельное исправление native date/number/select controls, отсутствовавшее в main с каталогом кандидатов. Его необходимо сохранить. Объединённая конфигурация проверок форм запускает и candidate-forms, и desktop form alignment в Chromium/WebKit.

## Проверка результата

После обновления проверьте:

- точный каталог релиза в labels frontend/backend и опубликованный порт 8088;
- здоровье frontend/backend/mcp и сохранённых PostgreSQL/MinIO/ClamAV;
- внутренний backend `/actuator/health`, кандидатские маршруты в `/v3/api-docs` и применение Liquibase changeset 015;
- внешний HTTP 200 и наличие кандидатских маршрутов в новой frontend-сборке;
- сохранение существующих runtime-параметров и отсутствие смены сети/хранилищ.

Публикация текстов `candidates.*` выполняется отдельно администратором через действующий редактор локализации. Не копируйте тестовые переводы или юридические документы в рабочую базу.
